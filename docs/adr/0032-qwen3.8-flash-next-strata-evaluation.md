# ADR-0032: Qwen3.8-Flash-Next on the Strata engine — evaluation result

- **Status:** Accepted (evaluation result). Production is **unchanged**; integration is a follow-up the owner has not yet approved.
- **Date:** 2026-10-24
- **Deciders:** @bradrlaw (+ Copilot CLI)
- **Related:** [ADR-0030](0030-llama-cpp-b11819-update.md) (llama.cpp b11819, the control),
  [ADR-0015](0015-llama-swap-serving-modes.md) (serving modes), [ADR-0028](0028-host-firewall-ufw.md)
  (container to host ports), [ADR-0031](0031-vision-projectors-on-chat-slots.md) (vision)

## Context
Qwen3.8-Flash-Next is a 125B-parameter MoE with about 6B active parameters. It is too big for the
V100s under llama.cpp (whose sparse attention path needs Turing or newer, so it runs dense on sm_70).
The **Strata** engine (v0.2.2, built from source for sm_70) keeps hot experts on the GPUs and streams
the rest from pinned RAM. The research plan set the rules before any test ran:
- Strata becomes a **second engine** only if it passes the adoption criteria below; otherwise llama.cpp is the answer.
- Owner policy: **Q4_K_XL or Q8_0 only**, context capped at **512K** (1M deferred), eval files on NVMe **at most 250 GB**.
- Q8_0 replaces Q4_K_XL only if decode is at least 30 tok/s and quality is at least 2 points better.
- Production must be intact outside the eval windows (daily trio unloaded only inside windows).

## Decision
**Strata with UD-Q4_K_XL passes the adoption criteria and is the Flash-Next serving candidate.
Q8_0 is a measured reference only. Nothing was switched on in production.**

Full numbers and method: [benchmarking.md](../benchmarking.md#qwen38-flash-next-on-the-strata-engine-vs-llamacpp-20261023-24).
Raw data: `docs/data/flash-next/`. Harness: `scripts/flash-eval/`.

| Criterion | Result |
|---|---|
| Speed: decode at least 45 tok/s short and 40 at 256K; prefill at least 900 tok/s at 32K | Pass. 72-78 short, 94 code, 72 / 94 at 512K ctx; prefill 1,495 at 32K (llama.cpp control 27 / 41 and about 115). |
| Pinned RAM at most about 100 GiB at 512K, cold load at most 5 min | Pass. One 500K prompt ran with about 45 GB of RAM still free; load is 83-98 s. |
| Needles at least 90% at 512K | Pass. 9/9 at 250K-500K on real text; the two earlier misses were the model's prompt-injection refusal of an "IMPORTANT: vault code" needle, not retrieval. |
| 1. Same-prompt parity within sampling noise | Pass on quality, **not** byte-identical: 3/20 greedy outputs match, but llama.cpp matches itself only 6/20 when MTP is toggled. Tool calls 30/30, JSON mode and `</think>` handling pass. |
| 2. Zero crashes/Xid and a clean `/unload` | Pass, with a **30-minute soak (owner shortened it from 4 h)**: 286 requests, 0 failures, 0 Xid, `/unload` frees both V100s twice. |
| 3. Pinned-RAM guard never trips at 512K | Pass (not tripped; VRAM-low warnings only). |
| 4. Quality at tail-skip 0 at least equal to the control | Pass. GSM8K 0.99 vs 0.99; code evals 12/15 vs 13/15 at 100%, and the one hard failure (dungeon r2 syntax error) happens on both engines. |
| 5. Speed gates | Pass (above). |
| 6. Loopback only, no new LAN exposure | Pass. The test ran behind a private llama-swap on 127.0.0.1:9091; the firewall was not touched. |

The default `STRATA_ROUTE_TAIL_SKIP=7` was kept: it measured no quality loss (GSM8K 0.99 for both 0 and 7) and
saves about 8% decode.

Q8_0 (Strata, RAM-budget mode): 32 / 49 tok/s short / code (28 / 41 at 512K), 15/15 code evals at 100% and the
same GSM8K, so it does not clear the 2-point rule and costs more than half the speed. Its shards were
deleted from NVMe after Window 3 (the pack stays; re-download is about 21 minutes).

## Consequences
- Positive: a 125B MoE runs at 72-94 tok/s with up to 512K context on the existing V100s; Strata decodes
  2.3-2.7x faster and prefills about 12x faster than the llama.cpp control on the same file, at equal measured quality.
- Negative / trade-offs:
  - **It needs both V100s and about 80 GiB of pinned RAM.** While it serves, `coding`, `big`, `chat` and
    anything else on idx1/idx2 must be unloaded, so it would be its own serving mode, not an addition to `daily`.
  - Vision works through Strata's CPU encoder (Window 6, 6/6 image checks, 4-5 s per image, slower than `big`'s GPU mmproj) and there is no batching gain: 4 clients get about 66 tok/s in total.
  - Strata is a young third-party engine built from source under `src/strata` (gitignored); its decode is
    not bit-identical to llama.cpp.
  - Outputs at temperature 0 diverge from llama.cpp after about 70-90 characters. Do not use output
    equality as a regression test across engines; use the evals.
- Follow-ups / things to watch (**none done yet, all need the owner's approval**):
  1. Add a `flash` entry to `config/llama-swap.base.yaml` (`exec` the Strata server, `checkEndpoint: /health`,
     `healthCheckTimeout` 300 or more, same recipe as `docs/data/flash-next/window4/ls.yaml`), a matching
     LiteLLM `model_list` entry, and a mode overlay that unloads the daily trio. Mind that `/unload` is a **GET**.
  2. If containers must reach it directly, ADR-0028 applies; through LiteLLM no firewall change is needed.
  3. A full 4-hour soak was not run. Re-run a long soak before relying on it unattended.
  4. (Done in Window 6) vision enabled via the `strata-vision` CPU build and `strata-w6.json`; head-to-head vs `big` in `docs/benchmarking.md`: equal quality, Flash-Next about 2x faster decode.
  5. The 1M-token context, the HTML/dungeon visual rubric axes (no headless browser) and the Hermes
     `v100-perf-scout` run on Flash-Next remain open.
  6. Delete the Q4 shards (111 GB on NVMe, copy on the bulk drive) when the owner says so.

## Alternatives considered
- **llama.cpp b11819 for Flash-Next** - works with MTP but decodes 21-41 tok/s and prefills about 115 tok/s, 2.3-2.7x slower at decode and about 12x slower at prefill than Strata at the same quality. Kept as the control and fallback.
- **Q8_0 as the serving quant** - fits and scored 15/15, but is about half the speed and did not beat Q4 by the required margin.
- **IQ3/IQ1 quants (ISTA GSQ-RCO IQ3_S, Coder IQ1_M)** - rejected by owner policy (Q4 or Q8 only; Q3 and lower have quality-loss reports).
